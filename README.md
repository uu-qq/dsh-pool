# dsh-pool — 一个模型卡住了，自动换下一个接着聊

给 [DeepSeek Harness (dsh)](https://github.com/deepseek-ai/deepseek-harness) 用的插件。

你一定遇到过：聊得好好的，模型突然卡住不动了，整个任务停摆，
还得你手动把刚才的话再发一遍 —— 时间和钱（token）都白烧。
这个插件把几个模型排成一个队：先用第一个，**它一卡住就自动换下一个**，
对话不中断，你什么都不用做。

## 新手三步上手

**第一步：装上。**

```sh
dsh plugin --profile web add github:uu-qq/dsh-pool
```

**第二步：写一份“排队名单”。** 新建一个文件 `~/.dsh/dsh-pool.json`，
把下面这份抄过去，只改每段里那几个值（仓库里也有现成模板
[`pool.example.json`](pool.example.json)，中转站用户看
[`pool.relay.example.json`](pool.relay.example.json)）：

```json
[
  {
    "name": "主力",
    "baseUrl": "https://服务商给的接口地址/v1",
    "model": "模型名",
    "apiKeyEnv": "POOL_KEY_1"
  },
  {
    "name": "备胎",
    "baseUrl": "https://另一个服务商的接口地址/v1",
    "model": "模型名",
    "apiKeyEnv": "POOL_KEY_2"
  }
]
```

这几个值去哪找：**接口地址和模型名**在服务商的网站上（一般叫“API 地址 / Base URL”
和“模型列表”）；**密钥**在服务商网站的控制台里生成，然后放进环境变量
（上面名单里写的 `POOL_KEY_1` 就是环境变量的名字，不要把密钥直接写进文件）。
Windows（PowerShell）：

```powershell
setx POOL_KEY_1 "你的密钥"
setx POOL_KEY_2 "另一个密钥"
```

macOS / Linux：

```sh
export POOL_KEY_1="你的密钥"
export POOL_KEY_2="另一个密钥"
```

名单从上往下就是尝试顺序：先主力，卡住换备胎，还可以继续往下加。

**第三步：在 dsh 里告诉它走这个队。** 打开 dsh 设置 → 模型 → 添加自定义提供方：

- 类型选 **OpenAI 兼容（openai-completions）**
- 接口地址填 `http://127.0.0.1:17890/v1`（这是插件在你电脑上开的“队头”）
- 密钥随便填一个占位字符就行（真密钥在上面第二步的环境变量里）
- 模型名填名单里任意一个 `name`（从它开始排），或随便填（从队头开始）

完事，之后正常聊天，切换都在后台自动发生。

## 它自己会做的事（不用你管）

- **卡住就换**：一个模型迟迟不回话（超时）、太挤被挡回来（429）、服务器出错（5xx）、
  连不上，立刻换下一个
- **假成功也换**：有的中转站嘴上说成功、其实返回的是错误，它拆开看穿了照样换；
  回答刚开始就出错的也一样
- **老出错的先晾一会儿**：同一个成员连续出错 3 次，就让它休息 60 秒起步
  （再犯翻倍，最长 8 倍），免得每次都在坏成员身上白等；它恢复了自动回来。
  这招叫“熔断”，就是家里保险丝那个意思
- **不该换的不换**：你把话写错了（参数错误 400），换谁都一样，就不折腾了，直接告诉你错在哪

## 看懂它在干什么

在 dsh 里让它调 `pool_status`，或者浏览器打开网关的 `/health`，能看到队伍和最近的切换记录：

```
模型池运行中：http://127.0.0.1:17890/v1
成员顺序：主力（MiMo-V2.6-Flash） → 备胎（GLM-5.3-Flash）
熔断（保护）状态：备胎 连续出错 3 次，正在休息中
最近请求：
  2026-11-18T03:12:00 主力:timeout → 备胎:ok
```

读法很简单：一行就是一次请求走过的路，`timeout` 是等太久、`ok` 是最后由它答上了。

## 几个词先说清（附科普贴）

- **熔断是什么**（为什么坏成员要“休息”）：推荐这篇保险丝版科普
  [《什么是熔断？》— 犬小哈教程](https://www.quanxiaoha.com/java-interview/what-is-circuit-breaker)
- **中转站是什么**：推荐腾讯云开发者社区这篇
  [《API 中转站是什么？原理、组成与它和 AI 网关的区别》](https://cloud.tencent.com/developer/article/2745464)
- **API / 密钥 / 环境变量是什么**：推荐这篇点餐版科普
  [《API 是什么》— LearnPy](https://www.learnpy.online/zh/python-quickstart/module-33_llm-api/33.2-what-is-an-api.html)

## 必须知道的两件事

- **回答已经开始往外蹦字之后断掉的，救不回来**：只能在第一个字出来之前换人，
  这是所有这类工具共同的限制，不是偷懒
- **被换掉的那次，对方可能还在后台把答案生成完**，那部分费用省不回来；
  这个插件省的是你不用重发整段对话、任务不用从头再来

## 进阶（看不懂可以跳过）

名单也可以用环境变量 `DSH_POOL_ENTRIES` 直接给，或用插件配置 `poolFile` 指定别的文件。
插件配置（都可不填，默认值就是按大多数中转站的脾气调好的通用配置）：

```yaml
        port: 17890              # 队头地址的端口
        poolFile: ''             # 名单文件路径，空 = 用 ~/.dsh/dsh-pool.json
        attemptTimeoutMs: 60000  # 每个成员最多等多久（60 秒没动静就换）
        breakerThreshold: 3      # 连续出错几次开始让它休息（0 = 关掉熔断）
        breakerCooldownMs: 60000 # 休息起步时长，之后自动翻倍
```

每个成员还可以单独写 `"timeoutMs"` 覆盖全局超时。不装插件也能单独跑这个网关：

```sh
node lib/cli.js --config pool.example.json --port 17890
# 然后把任何兼容 OpenAI 接口的软件的地址指向 http://127.0.0.1:17890/v1
```

什么时候换、什么时候不换，完整对照：超时 ✅ / 429 太挤 ✅ / 5xx 对方出错 ✅ /
连不上 ✅ / 这家没这个模型 ✅ / 密钥不被认 ✅（下一家可能用不同的密钥）/
你把请求写错了 400、413 ❌（换谁都一样）。

开发：`npm test` 跑全部测试。目录：`lib/pool.js` 网关本体（排队尝试、熔断都在这）、
`lib/policy.js` 换不换的判断、`lib/index.js` 插件入口、`lib/cli.js` 独立运行入口。

## 说明

- 网关只在你自己电脑上监听（127.0.0.1），不对外；密钥只从环境变量读，不落盘、不进日志。
- 全部成员都失败时，网关会明确告诉你每个成员是怎么失败的，不会假装成功。
- dsh 还在开发者预览期，插件接口可能变化；本插件按 2026-11 的插件规范编写。MIT 许可。
